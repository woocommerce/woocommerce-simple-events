# WooCommerce Simple Events

A **test plugin** that exercises WooCommerce's dual-code / GraphQL API
infrastructure from outside core. It defines a small event-registration
schema (events, sessions, attendees, statistics, and a handful of
queries and mutations) and uses it to demonstrate, end to end, the
pieces a plugin can build its own dual API from: the code-API
conventions, custom authentication and authorization, schema metadata,
pagination, and the build pipeline.

It has no production use; it exists to validate (and document, alongside
the [Dual API docs](https://developer.woocommerce.com/docs/apis/dual-api/))
that a sibling plugin can reuse the infrastructure.


## What it demonstrates

| Area | Where |
| --- | --- |
| Custom authentication / principal | `Api/Infrastructure/PrincipalResolver`, `EventsPrincipal` |
| Custom class resolver | `Api/Infrastructure/ClassResolver` |
| Custom HTTP status resolver | `Api/Infrastructure/HttpStatusResolver` |
| Custom authorization attributes | `Api/Attributes/RequiresScope`, `OwnerOrScope` |
| Operation / type / field / input gates | queries, mutations, `Event`, `Attendee`, `EventStats`, input types |
| `authorize()` composed with `$_preauthorized` | `Mutations/CancelEvent` |
| `$_parent` / `$_metadata` / `$_args` opt-in slots | `OwnerOrScope` (`$_parent`) |
| Enum type | `Api/Enums/EventStatus` |
| Custom scalar | `Api/Scalars/DateTime` |
| Interface (PHP trait, two implementers) | `Api/Interfaces/ScheduledItem` (`Event`, `Session`) |
| Relay-style connection / pagination | `Queries/ListEventsConnection` (`eventsConnection`) |
| `#[ArrayOf]` with a class element type | `Event::$sessions` |
| `#[Deprecated]` / `#[Ignore]` | `Event::$location` / `Event::$audit_token` |
| Metadata attributes (`#[Internal]`, `#[Experimental]`, custom) | `Event::$sequence`, `eventsConnection`, `Api/Attributes/Team` |
| `_apiMetadata` discovery + opt-out | `#[HiddenFromMetadataQuery]` on `Event::$internal_notes` |
| Selection-aware resolving (`$_query_info`) | `Queries/GetStatistics` |
| `TracksProvidedFields` (`was_provided()`) | `InputTypes/RegistrationInput` |

## Requirements

- PHP 8.1 or later.
- A recent WooCommerce build with the dual-code GraphQL API. The plugin
  uses the granular-authorization features (property-level
  `#[RequiredCapability]` / `#[PublicAccess]`, the opt-in `$_metadata` /
  `$_args` / `$_parent` slots on attribute `authorize()` methods, and the
  `_apiMetadata.authorization` slice), which are part of trunk.
- The `dual_code_graphql_api` feature flag enabled in WooCommerce.

## State

Events and attendees live in WordPress's object cache under the `wcse`
group. The store seeds itself on first access (two events, each with a
couple of sessions, and three attendees), and mutations persist across
requests as long as the host site has a **persistent object-cache
backend** (Redis, Memcached, ...). Under WordPress's default in-memory
cache the state still works *within* a request but resets between
requests. Flush with `wp cache flush` to re-seed.

## Roles, scopes & authentication

Authentication is custom (not WordPress users): HTTP Basic auth with one
fixed user per role, the password always `password`. The username
doubles as the role. This is what a plugin's own `PrincipalResolver` +
principal class look like.

| Username    | Password   | Role        |
| ----------- | ---------- | ----------- |
| `organizer` | `password` | organizer   |
| `manager`   | `password` | manager     |
| `finance`   | `password` | finance     |
| (none)      | (none)     | anonymous   |

Any other username or wrong password is rejected as `401 Unauthorized`
(the resolver throws `InvalidTokenException`).

Roles do **not** drive authorization directly. Each role expands to a
set of *scopes* (capability-like strings); the authorization attributes
check scopes. Different roles can share scopes, so type-level and
field-level gates AND-compose in a non-trivial way - e.g. a type that
requires `events:read` (every role has it) plus a field that requires
`events:revenue` (only `finance` has it) yields a field that only
`finance` can read, while the rest of the type stays readable for any
authenticated caller.

| Scope                    | organizer | manager | finance |
| ------------------------ | :-------: | :-----: | :-----: |
| `events:read`            |     ✓     |    ✓    |    ✓    |
| `events:edit`            |           |    ✓    |         |
| `events:waitlist`        |           |    ✓    |         |
| `events:revenue`         |           |         |    ✓    |
| `events:internal_notes`  |           |    ✓    |         |
| `attendees:read_pii`     |     ✓     |    ✓    |         |
| `attendees:payment`      |           |         |    ✓    |

Native GraphQL introspection (`__schema` / `__type`) and the
`_apiMetadata` discovery query are both gated on the principal's
`can_introspect()`. `EventsPrincipal` grants this only to the `manager`
role; other roles and anonymous callers can call mutations / queries
but cannot enumerate the schema's shape or its declared gates.

## Authorization

The plugin defines two custom authorization attributes (in
`src/Api/Attributes/`):

- **`#[RequiresScope($scope)]`**: grants when the principal holds the
  named scope. Targets class (query / mutation / type) and property
  (output / input field).
- **`#[OwnerOrScope($scope)]`**: grants if the principal owns the
  parent object (matches `$_parent->organizer_login`) or holds the
  named scope. Exercises the `$_parent` opt-in slot.

The core `#[PublicAccess]` attribute marks queries and mutations
intentionally exposed to anonymous callers. The core
`#[HiddenFromMetadataQuery]` marker is composed alongside
`#[RequiresScope]` to gate a target at runtime while hiding its row from
`_apiMetadata` (see `Event::$internal_notes`).

`EventReadableTrait` (in `src/Api/Authorization/`) carries a class-level
`#[RequiresScope('events:read')]`; a type that `use`s it inherits the
gate on every field (see `EventStats`), demonstrating trait-level
authorization.

`CancelEvent` shows a command's own `authorize()` method composed with
the attribute decision via `$_preauthorized`: managers pass through the
class-level `#[RequiresScope('events:edit')]`, and the method widens
that to also allow the event's own organizer.

### Field surface

| Target | Gate | Notes |
| --- | --- | --- |
| `Event` basic fields | public | id, name, description, date, status, sessions, ... - no gate |
| `Event.waitlist_size` | `#[OwnerOrScope('events:waitlist')]` | event organizer (per row) **or** anyone with `events:waitlist`; `$_parent` demo |
| `Event.revenue` | `#[RequiresScope('events:revenue')]` | finance only |
| `Event.internal_notes` | `#[RequiresScope('events:internal_notes')]` + `#[HiddenFromMetadataQuery]` | manager only at runtime; row absent from `_apiMetadata` |
| `Attendee` (whole type) | `#[RequiresScope('events:read')]` (direct on the class) | type-level floor: any authenticated event consumer; anonymous sees no field of any attendee |
| `Attendee.name / email` | type + `#[RequiresScope('attendees:read_pii')]` | AND - organizer + manager (the two roles holding both scopes) |
| `Attendee.paid_amount` | type + `#[RequiresScope('attendees:payment')]` | AND - finance only |
| `EventStats` (whole type) | `#[RequiresScope('events:read')]` via `EventReadableTrait` | every role holds `events:read`; the type-level gate is the floor |
| `EventStats.revenue_total` | type + `#[RequiresScope('events:revenue')]` | AND - only finance has both scopes |
| `EventStats.paid_attendees_count` | type + `#[RequiresScope('attendees:payment')]` | AND - only finance has both scopes |
| `RegistrationInput.paid_amount` | `#[RequiresScope('attendees:payment')]` | input-side gate; finance can pre-set it on registration |
| `RegistrationInput.internal_notes` | `#[RequiresScope('events:internal_notes')]` | input-side gate; managers only |
| `UpdateEventInput` (whole input) | `#[RequiresScope('events:edit')]` | class-level on the input type; gates fire per provided field |

## Schema features beyond authorization

- **Enum**: `EventStatus` (`DRAFT` / `PUBLISHED` / `CANCELLED` /
  `COMPLETED` / `OTHER`), exposed on `Event.status` with a `raw_status`
  escape hatch.
- **Custom scalar**: `DateTime` (ISO 8601), applied to the shared
  `date` field via the interface.
- **Interface**: `ScheduledItem` (a PHP trait under `Interfaces/`)
  contributes `id` + `date` to both `Event` and `Session`.
- **Connection / pagination**: `eventsConnection` returns a Relay-style
  `Connection` of `Event` using `PaginationParams`.
- **Nested objects + `#[ArrayOf]`**: `Event.sessions` is a list of the
  `Session` type.
- **`#[Deprecated]` / `#[Ignore]`**: `Event.location` (deprecated alias
  of `venue`) and `Event.audit_token` (omitted from the schema).
- **Metadata**: `#[Internal]` on `Event.sequence`, `#[Experimental]` on
  the `eventsConnection` query, and a plugin-defined `#[Team]` metadata
  attribute on the `Session` type.
- **Custom HTTP status**: `HttpStatusResolver` lets a client force the
  status of a successful response with an `X-Status-Code` header.
- **Selection-aware resolving**: `statistics` reads `$_query_info` and
  skips the revenue aggregates when the client didn't select them.

## Building

The generated GraphQL layer (`src/Internal/Api/Autogenerated/`) is
committed, so a fresh clone works without building. Regenerate it
whenever a code-API class changes, and commit the regenerated tree
together with the source change:

```sh
composer install   # once, after cloning
pnpm run build:api
```

`composer build:api` and `php bin/build-api.php` do the same thing.

### Locating WooCommerce

By convention the build script expects WooCommerce's plugin tree at
`../woocommerce/plugins/woocommerce` relative to this plugin's root.
Override with `WC_PATH`:

```sh
WC_PATH=/path/to/woocommerce/plugins/woocommerce pnpm run build:api
```

## Querying

After activating the plugin in WordPress, post a GraphQL query to
`/wp-json/wc/graphql/simple-events`:

```sh
# Anonymous - sees only public fields
curl -X POST https://example.com/wp-json/wc/graphql/simple-events \
  -H 'Content-Type: application/json' \
  -d '{"query":"{ event(id: 1) { name venue status date } }"}'

# Paginated list of events
curl -X POST https://example.com/wp-json/wc/graphql/simple-events \
  -H 'Content-Type: application/json' \
  -d '{"query":"{ eventsConnection(first: 1) { edges { cursor node { name } } page_info { has_next_page end_cursor } total_count } }"}'

# Finance - can read revenue
curl -X POST https://example.com/wp-json/wc/graphql/simple-events \
  -H 'Content-Type: application/json' \
  -u finance:password \
  -d '{"query":"{ event(id: 1) { name revenue } }"}'

# Organizer (user `organizer`) - owner-gate grants on their event
curl -X POST https://example.com/wp-json/wc/graphql/simple-events \
  -H 'Content-Type: application/json' \
  -u organizer:password \
  -d '{"query":"{ event(id: 1) { waitlist_size } }"}'

# Manager - can write internal notes via the gated mutation
curl -X POST https://example.com/wp-json/wc/graphql/simple-events \
  -H 'Content-Type: application/json' \
  -u manager:password \
  -d '{"query":"mutation { updateEvent(id: 1, input: { internal_notes: \"reviewed\" }) { id } }"}'

# Force a custom HTTP status on a successful response (HttpStatusResolver)
curl -i -X POST https://example.com/wp-json/wc/graphql/simple-events \
  -H 'Content-Type: application/json' -H 'X-Status-Code: 418' \
  -d '{"query":"{ event(id: 1) { name } }"}'
```

### Discovery

The schema's declared gates can be inspected via `_apiMetadata`. Access
is gated by the principal: `EventsPrincipal` declares `can_introspect()`
returning `true` only for the `manager` role, and the framework's
`MetadataController` falls back to `can_introspect()` when the principal
does not declare a separate `can_query_metadata()`. Calls from other
principals receive `UNAUTHORIZED` / `FORBIDDEN`.

```sh
curl -X POST https://example.com/wp-json/wc/graphql/simple-events \
  -u manager:password \
  -H 'Content-Type: application/json' \
  -d '{"query":"{ _apiMetadata { type field entries { name value } authorization { attribute args } } }"}'
```

Targets carrying `#[HiddenFromMetadataQuery]` do not appear in this
output - `shows_in_metadata_query()` returns `false` and the framework
omits the whole row.

### Deny shape

Field-level denies carry a structured `subject` payload identifying the
type, field and deciding attribute:

```json
{
  "errors": [
    {
      "message": "You do not have permission to perform this action.",
      "path": ["event", "revenue"],
      "extensions": {
        "code": "FORBIDDEN",
        "subject": {
          "type": "Event",
          "field": "revenue",
          "attribute": "RequiresScope"
        }
      }
    }
  ]
}
```

Anonymous callers receive `UNAUTHORIZED` (HTTP 401) instead of `FORBIDDEN`.
