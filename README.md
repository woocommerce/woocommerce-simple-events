# WooCommerce Simple Events

A test plugin that exercises WooCommerce's dual-code / GraphQL API
infrastructure from outside core, focused on the **granular (field-level)
authorization** surface. It defines a tiny event-registration schema —
events, attendees, and two mutations — and gates output fields and input
fields with three plugin-defined authorization attributes.

The plugin exists to validate that sibling WooCommerce plugins can use
the field-level authorization mechanism; it has no production use.

## Requirements

- PHP 8.1 or later.
- A WooCommerce build that ships the dual-code GraphQL API plus the
  granular-authorization extensions (`#[RequiredCapability]` /
  `#[PublicAccess]` on properties, opt-in `$_metadata` / `$_args` /
  `$_parent` slots on attribute `authorize()` methods, and
  `_apiMetadata.authorization`).
- The `dual_code_graphql_api` feature flag enabled in WooCommerce.

## State

Events and attendees live in WordPress's object cache under the `wcse`
group. The store seeds itself on first access (two events, three
attendees), and mutations persist across requests as long as the host
site has a **persistent object-cache backend** (Redis, Memcached, …).
Under WordPress's default in-memory cache the state still works *within*
a request but resets between requests. Flush with `wp cache flush` to
re-seed.

## Roles, scopes & authentication

HTTP Basic auth with one fixed user per role; the password is always
`password`. The username doubles as the role.

| Username    | Password   | Role        |
| ----------- | ---------- | ----------- |
| `organizer` | `password` | organizer   |
| `manager`   | `password` | manager     |
| `finance`   | `password` | finance     |
| (none)      | (none)     | anonymous   |

Any other username or wrong password is rejected as `401 Unauthorized`.

Roles do **not** drive authorization directly. Each role expands to a
set of *scopes* (capability-like strings); the authorization attributes
check scopes. Different roles can share scopes, so type-level and
field-level gates AND-compose in a non-trivial way — e.g. a type that
requires `events:read` (every role has it) plus a field that requires
`events:revenue` (only `finance` has it) yields a field that only
`finance` can read, while the rest of the type stays readable for any
authenticated caller.

| Scope                    | organizer | manager | finance |
| ------------------------ | :-------: | :-----: | :-----: |
| `events:read`            |     ✓     |    ✓    |    ✓    |
| `events:edit`            |           |    ✓    |         |
| `events:waitlist`        |           |    ✓    |         |
| `events:revenue`         |           |         |    ✓    |
| `events:internal_notes`  |           |    ✓    |         |
| `attendees:read_pii`     |     ✓     |    ✓    |         |
| `attendees:payment`      |           |         |    ✓    |

Native GraphQL introspection (`__schema` / `__type`) and the
`_apiMetadata` discovery query are both gated on the principal's
`can_introspect()`. `EventsPrincipal` grants this only to the `manager`
role; other roles and anonymous callers can call mutations / queries
but cannot enumerate the schema's shape or its declared gates.

## Authorization attributes

The plugin defines two custom authorization attributes (in
`src/Api/Attributes/`):

- **`#[RequiresScope($scope)]`** — grants when the principal holds the
  named scope. Targets class (query / mutation / type) and property
  (output / input field).
- **`#[OwnerOrScope($scope)]`** — grants if the principal owns the
  parent object (matches `$_parent->organizer_login`) or holds the
  named scope. Exercises the `$_parent` opt-in slot.

The core `#[PublicAccess]` attribute is used for queries and mutations
intentionally exposed to anonymous callers. The core
`#[HiddenFromMetadataQuery]` marker is composed alongside
`#[RequiresScope]` to gate a target at runtime while hiding its row
from `_apiMetadata` (see `Event::$internal_notes`).

## Field surface

| Target                              | Gate                                                       | Notes                                                                              |
| ----------------------------------- | ---------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| `Event.id / name / description / …` | public                                                     | basic event details, no gate                                                       |
| `Event.waitlist_size`               | `#[OwnerOrScope('events:waitlist')]`                       | event organizer (per row) **or** anyone with `events:waitlist`; `$_parent` demo    |
| `Event.revenue`                     | `#[RequiresScope('events:revenue')]`                       | finance only                                                                       |
| `Event.internal_notes`              | `#[RequiresScope('events:internal_notes')]` + `#[HiddenFromMetadataQuery]` | manager only at runtime; row absent from `_apiMetadata`            |
| `Attendee` (whole type)             | `#[RequiresScope('events:read')]` (direct on the class)    | type-level floor: any authenticated event consumer; anonymous sees no field of any attendee |
| `Attendee.id / event_id`            | (type only)                                                | resolved when the type-level `events:read` gate passes                             |
| `Attendee.name / email`             | type + `#[RequiresScope('attendees:read_pii')]`            | AND — organizer + manager (the two roles holding both scopes)                      |
| `Attendee.paid_amount`              | type + `#[RequiresScope('attendees:payment')]`             | AND — finance only                                                                 |
| `EventStats` (whole type)           | `#[RequiresScope('events:read')]` via `EventReadableTrait` | every role holds `events:read`; the type-level gate is the floor                   |
| `EventStats.revenue_total`          | type + `#[RequiresScope('events:revenue')]`                | AND — only finance has both scopes                                                 |
| `EventStats.paid_attendees_count`   | type + `#[RequiresScope('attendees:payment')]`             | AND — only finance has both scopes                                                 |
| `RegistrationInput.paid_amount`     | `#[RequiresScope('attendees:payment')]`                    | input-side gate; finance can pre-set it on registration                            |
| `RegistrationInput.internal_notes`  | `#[RequiresScope('events:internal_notes')]`                | input-side gate; managers only                                                     |
| `UpdateEventInput` (whole input)    | `#[RequiresScope('events:edit')]`                          | class-level on the input type; gates fire per provided field                       |

## Building

Run once after cloning, and whenever a code-API class changes:

```sh
composer install
pnpm run build:api
```

`composer build:api` and `php bin/build-api.php` do the same thing.

### Locating WooCommerce

By convention the build script expects WooCommerce's plugin tree at
`../woocommerce/plugins/woocommerce` relative to this plugin's root.
Override with `WC_PATH`:

```sh
WC_PATH=/path/to/woocommerce/plugins/woocommerce pnpm run build:api
```

## Querying

After activating the plugin in WordPress, post a GraphQL query to
`/wp-json/wc/graphql/simple-events`:

```sh
# Anonymous — sees only public fields
curl -X POST https://example.com/wp-json/wc/graphql/simple-events \
  -H 'Content-Type: application/json' \
  -d '{"query":"{ event(id: 1) { name venue capacity } }"}'

# Finance — can read revenue
curl -X POST https://example.com/wp-json/wc/graphql/simple-events \
  -H 'Content-Type: application/json' \
  -u finance:password \
  -d '{"query":"{ event(id: 1) { name revenue } }"}'

# Organizer (user `organizer`) — owner-gate grants on their event
curl -X POST https://example.com/wp-json/wc/graphql/simple-events \
  -H 'Content-Type: application/json' \
  -u organizer:password \
  -d '{"query":"{ event(id: 1) { waitlist_size } }"}'

# Manager — can write internal notes via the gated mutation
curl -X POST https://example.com/wp-json/wc/graphql/simple-events \
  -H 'Content-Type: application/json' \
  -u manager:password \
  -d '{"query":"mutation { updateEvent(id: 1, input: { internal_notes: \"reviewed\" }) { id } }"}'
```

### Discovery

The schema's declared gates can be inspected via `_apiMetadata`. Access
is gated by the principal: `EventsPrincipal` declares
`can_introspect()` returning `true` only for the `manager` role, and
the framework's `MetadataController` falls back to `can_introspect()`
when the principal does not declare a separate `can_query_metadata()`.
Calls from other principals receive `UNAUTHORIZED` / `FORBIDDEN`.

```sh
curl -X POST https://example.com/wp-json/wc/graphql/simple-events \
  -u manager:password \
  -H 'Content-Type: application/json' \
  -d '{"query":"{ _apiMetadata { type field authorization { attribute args } } }"}'
```

Targets carrying `#[HiddenFromMetadataQuery]` do not appear in this
output — `shows_in_metadata_query()` returns `false` and the
framework omits the whole row.

### Deny shape

Field-level denies carry a structured `subject` payload identifying the
type, field and deciding attribute:

```json
{
  "errors": [
    {
      "message": "You do not have permission to perform this action.",
      "path": ["event", "revenue"],
      "extensions": {
        "code": "FORBIDDEN",
        "subject": {
          "type": "Event",
          "field": "revenue",
          "attribute": "RequiresRole"
        }
      }
    }
  ]
}
```

Anonymous callers receive `UNAUTHORIZED` (HTTP 401) instead of `FORBIDDEN`.
